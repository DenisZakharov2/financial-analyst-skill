# Финансовый аналитик

Считает метрики по клиентской выгрузке (портфель, воронка и TAT, финансы,
юнит-экономика, сегментация RFM + Risk, A/B-пилоты и сравнение срезов) и по
агрегированной рыночной статистике (структура, динамика, сезонность, аномалии,
лаговая причинность Грейнджера, каскадный прогноз). Числа считает скрипт,
выводы пишет агент по шаблону. Инвестиционных рекомендаций скилл не даёт и
лицензионных услуг не заменяет.

## Когда использовать

- Нужно посчитать портфель: объём, счета, клиенты, средние значения, PAR 30/60/90, доля топ-10 клиентов.
- Нужно разобрать воронку и TAT: конверсия этапов, потери, поэтапный TAT (p50/p75/p90/p95), SLA, зависший бэклог, выживаемость Каплана-Мейера.
- Нужно посчитать юнит-экономику: CAC, ARPU, LTV gross/net, LTV/CAC, окупаемость CAC.
- Нужно оценить финансовый блок: выручка, прямые расходы, валовая маржа, contribution, NIM.
- Нужно разобрать агрегированный ряд: структура, динамика, сезонные индексы, аномалии (робастный Z), корреляции, прогноз (линейный тренд или каскад Linear / ETS / ARX / SARIMAX).
- Нужно оценить пилот: A/B-тест с проверкой SRM и линеаризацией ratio-метрик либо квази-эксперимент DiD.
- Нужно разложить отклонение: PVM (объём, микс, ставка) и сдвиг просрочки PAR по Шепли.
- Нужно сегментировать клиентов: матрица RFM + Risk и кластеры.
- Нужно сравнить две выгрузки: сверка схем, портфельный Bridge (New / Churn / Expansion / Contraction, retention, NRR), P&L variance.
- Нужен готовый отчёт в DOCX/PDF/XLSX/PPTX/RTF/HTML с проверяемыми числами и контролем ПДн (`--pii-mode`).

## Когда не использовать

- Задача не про финансы, продукты, клиентов или рыночную статистику.
- Нужна инвестиционная рекомендация или услуга, требующая лицензии.
- В данных есть сырые персональные сведения, а проверка отключена (`--pii-mode=off`). Безопасный запуск с удалением колонок — `--pii-mode=redact`. Режим по умолчанию `strict` такой запуск останавливает.
- Нужен прогноз без истории: меньше 6 периодов для линейного тренда по умолчанию и меньше 3 периодов даже для `--forecast-model linear`. Структурные макромодели (DSGE) скилл не строит.

## Prerequisites

- Python 3.10+ (проверено на 3.12) и зависимости из `requirements.txt` с
  диапазонами версий (`pandas`, `numpy`, `scipy`, `matplotlib`, `plotly`, `openpyxl`,
  `python-docx`, `python-pptx`, `reportlab`, `xlrd`). Точный проверенный набор —
  `requirements.lock.txt`: `pip install -r requirements.lock.txt`. Пакетная установка
  `pip install -e .` дополнительно даёт команду `financial-analyst`.
- `scipy` нужен расширенным расчётам (A/B-тесты, тест Грейнджера, ETS). Без него
  базовый расчёт работает как прежде, а расширенные разделы не строятся.
- PostgreSQL (опционально): для источника данных `--source postgres` нужны
  `sqlalchemy>=2.0,<3` и `psycopg>=3.1,<4` (extra `postgres` в `pyproject.toml`
  или `pip install "sqlalchemy>=2.0,<3" "psycopg>=3.1,<4"`).
- Запускайте с `PYTHONDONTWRITEBYTECODE=1`: иначе в `scripts/` появится
  `__pycache__`, и сканеры безопасности пометят скилл как непрозрачный.
- Шрифт с кириллицей для PDF: берётся из matplotlib, отдельная установка не нужна.
  Если matplotlib недоступен, положите `DejaVuSans.ttf` в `assets/fonts/`.
- Сеть не требуется: Plotly встраивается в дашборд, внешних CDN нет.
- Входные файлы: CSV (UTF-8) или Excel, имена файлов = имена таблицы.

## Workflow

1. **Уточнить задачу.** Цель, решение, продукт, период, формат результата.
   Заполните `templates/brief.md`, если задача не разовая.
   *Критерий: известны период, разрез, формат и что считается результатом.*
2. **Подготовить конфиг (опционально).** Создайте `config.yaml` с настройками источника,
   прогноза, форматов вывода и порогов качества. Пример — `config.yaml.example`.
   *Критерий: конфиг валиден, приоритет CLI > YAML > ENV > defaults понятен.*
3. **Проверить данные и ПДн.** Запустите `scripts/analyze.py` с `--strict`
   (или `--pii-mode=redact` для автоматического удаления колонок ПДн и HMAC-псевдонимизации ключей).
   Для PostgreSQL: `--source postgres --pg-host ... --pg-database ...` (или ENV PGHOST, PGDATABASE...).
   *Критерий: в консоли 0 fail; предупреждения объяснены.*
4. **Согласовать метрики.** Выберите нужные из `references/metric-contracts.md`.
   *Критерий: у каждой метрики понятны зерно, знаменатель и краевой случай.*
5. **Посчитать.** Скрипт пишет `metrics.json`, `metrics.csv`, графики и отчёты.
   Расширенные расчёты включаются флагами: `--forecast-model auto` (каскад прогноза: Linear / ETS / ARX / SARIMAX),
   `--segment` (RFM + Risk и кластеры), `--ab-test` (оценка пилота),
   `--drivers` (PVM, сдвиг PAR, лаговые связи макропоказателей),
   `--credit-risk` (PD/LGD/EAD, Expected Loss, RWA по Basel IRB),
   `--cohort` (старт когорты и retention-кривые по возрасту в месяцах),
   `--plugins-dir` (пользовательские плагины метрик из внешних модулей),
   `--scenario-list standard` (сценарийный анализ: базовый, стресс, оптимистичный).
   Для больших выгрузок: `--chunksize N` (streaming CSV) или `--pg-chunksize N` (streaming PostgreSQL).
   *Критерий: `metrics.json` содержит разделы и допущения, код возврата 0.*
6. **Сверить числа.** Сравните headline-показатели с `metrics.csv`
   (разделы «Ключевые показатели» и «Юнит-экономика»).
   *Критерий: каждое число в тексте есть в `metrics.json`.*
7. **Написать выводы.** Используйте `templates/report.md.tmpl`.
   *Критерий: методология, допущения, интерпретация, риски, следующие шаги.*
8. **Отдать файлы.** Проверьте, что отчёт открывается и графики на месте.
   *Критерий: чек-лист из раздела «Проверка результата» пройден.*

## Входные данные

Клиентские таблицы: `clients`, `products`, `portfolio` (или `accounts`), `sales`
(или `applications`), `funnel_events`, `transactions`, `finance`.

Рыночные: `macro_deposits`, `macro_loans`, `macro_profit`, `macro_securities`,
`macro_survey`.

Полные схемы, типы и примеры — `references/data-dictionary.md`. Поддерживаются
CSV, XLS, XLSX. Широкие листы Excel разбираются адаптером `cbr_survey`: в режиме
`auto` он ищет книгу `stat_*.xlsx`, для другого имени нужен `--adapter cbr`.
Если таблицы нет, раздел пропускается с предупреждением, а не с нулём.

**Источник данных:**
- **Файлы (по умолчанию):** `--source files --data-dir ./data` — CSV/Excel в каталоге.
- **PostgreSQL:** `--source postgres --pg-host ... --pg-database ...` (или ENV PGHOST, PGDATABASE, PGUSER, PGPASSWORD, PGPORT, PGSCHEMA). Читает таблицы из схемы `public` (или `--pg-schema`). `macro_survey` в БД не хранится — для макро-раздела используйте файлы.

Опциональные поля для A/B: `experiment_group` (`control`/`treatment`), `pre_value`, `deals`.
Они читаются только при запуске с `--ab-test`.

## Выходные артефакты

- `metrics.json` — разделы, допущения, предупреждения, контроль качества, headline
  (`value` — строка для отчёта, `raw` — то же число для XLSX и сверки),
  `insights` — блок структурных наблюдений
  (`{type, driver, contribution_pct, severity, value}`: высокий PAR 30, низкий LTV/CAC,
  крупнейшая потеря воронки, макро-аномалии).
- `metrics.csv` — плоский список чисел для сверки: разделы отчёта, ключевые
  показатели и юнит-экономика (`section,metric,dimension,value`).
- `charts/*.png` — графики, только если в данных есть что рисовать.
- `financial_analyst_report.{docx,pdf,xlsx,pptx,rtf}` — отчёт с таблицами и графиками.
- `report.html` — интерактивный дашборд (при рыночном ряде) или статический отчёт.

Интерпретацию и рекомендации скрипт не пишет: это делает агент по шаблону.

## Контроль качества

- `references/quality-gates.md` — проверки входа: ПДн, ключи, связи, даты, валюты, дубли, SRM.
- `references/metric-contracts.md` — зерно, числитель, знаменатель, краевые случаи.
- `references/cohorts.md` — определение когорты и цензурирование.
- `scripts/finanalyst/reporting.py` (`lint_text`) — смешение алфавитов, двойные
  пробелы, латиница.

Жёсткие правила:

1. **Никаких чисел, которых нет в данных.** Запрещено подставлять «примерные»
   значения в таблицы и графики. Допущение — только отдельным блоком с пометкой.
2. **Никаких тихих NaN.** Если метрика не считается, это `null` и причина,
   а не ноль и не пустая ячейка.
3. **Одна метрика — одно определение.** Если определение меняется, меняется
   `metric-contracts.md`, а не отчёт.
4. **Строки `product_code = 'ALL'` не суммируются с детализацией.**
5. **Валюты не складываются без курса и даты курса.**
6. **Обезличивание не искажает финансовые суммы.** При `--pii-mode=redact`
   удаляются колонки ПДн и хэшируются только ключи связки (`client_id`, `account_id`).

## Подводные камни

- **PDF без шрифта.** Helvetica не содержит кириллицы. Скрипт подставляет DejaVu;
  если шрифт не найден, он падает с понятной ошибкой, а не рисует квадраты.
- **Смешение периодов.** Месяц `2026-01` и квартал `1к02` — разные типы.
  Нормализуйте в `period_start` и сортируйте по дате, не по строке.
- **Воронка без `application_id`.** Считать можно только по клиенту, и это
  допущение, а не конверсия заявок. См. `references/cohorts.md`.
- **Немонотонная воронка.** Если клиент появляется на позднем этапе без ранних
  событий, конверсия «от лида» не имеет смысла. Проверяйте монотонность.
- **Короткий ряд для сезонности.** Сезонные индексы строятся только при наличии
  минимум двух полных циклов (24 месяца или 8 кварталов).
- **`finance` с `ALL`.** Итоговая строка вместе с детализацией удваивает выручку.

## Проверка результата

```bash
PYTHONDONTWRITEBYTECODE=1 python scripts/analyze.py --data-dir assets/sample --out /tmp/fa --strict
python scripts/check_skill.py
```

Ожидается: код возврата 0, шесть файлов отчёта, `metrics.json` с разделами.
Дополнительно проверьте:

- PDF открывается и текст читается по-русски;
- XLSX: числа имеют числовой тип, а не текст;
- воронка монотонно убывает от лида к активации;
- PAR 30 ≥ PAR 60 ≥ PAR 90;
- в `metrics.json` нет `NaN`, только `null` с причиной.
