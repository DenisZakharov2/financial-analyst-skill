# Финансовый аналитик

Считает метрики по клиентской выгрузке (портфель, воронка, финансы, юнит-экономика)
и по агрегированной рыночной статистике (структура, динамика, аномалии, прогноз).
Числа считает скрипт, выводы пишет агент по шаблону. Инвестиционных рекомендаций
скилл не даёт и лицензионных услуг не заменяет.

## Когда использовать

- Нужно посчитать портфель: объём, клиенты, средние значения, PAR 30/60/90, концентрация.
- Нужно разобрать воронку: сколько доходит до каждого этапа, где теряется больше всего.
- Нужно посчитать юнит-экономику: CAC, ARPU, LTV, LTV/CAC, окупаемость.
- Нужно оценить финансовый блок: выручка, прямые расходы, валовая маржа, NIM.
- Нужно разобрать агрегированный ряд: структура, динамика, аномалии, прогноз.
- Нужен готовый отчёт в DOCX/PDF/XLSX/PPTX/RTF/HTML с проверяемыми числами.

## Когда не использовать

- Задача не про финансы, продукты, клиентов или рыночную статистику.
- Нужна инвестиционная рекомендация или услуга, требующая лицензии.
- В данных есть персональные сведения без обезличивания.
- Нужен A/B-анализ, кластеризация или ARIMA/ETS: в текущей версии их нет.
- Нужен точный прогноз факторов: скилл строит тренд и интервал ошибки, не причинную модель.

## Prerequisites

- Python 3.10+ (проверено на 3.12) и зависимости из `requirements.txt` в корне
  репозитория: `pip install -r requirements.txt`. Если скилл скопирован без
  репозитория, поставьте пакеты из `pyproject.toml` вручную.
- Шрифт с кириллицей для PDF: берётся из matplotlib, отдельная установка не нужна.
  Если matplotlib недоступен, положите `DejaVuSans.ttf` в `assets/fonts/`.
- Сеть не требуется: Plotly встраивается в дашборд, внешних CDN нет.
- Входные файлы: CSV (UTF-8) или Excel, имена файлов = имена таблиц.

## Workflow

1. **Уточнить задачу.** Цель, решение, продукт, период, формат результата.
   Заполните `templates/brief.md`, если задача не разовая.
   *Критерий: известны период, разрез, формат и что считается результатом.*
2. **Проверить данные.** Запустите `scripts/analyze.py` с `--strict`.
   *Критерий: в консоли 0 fail; предупреждения объяснены.*
3. **Согласовать метрики.** Выберите нужные из `references/metric-contracts.md`.
   *Критерий: у каждой метрики понятны зерно, знаменатель и краевой случай.*
4. **Посчитать.** Скрипт пишет `metrics.json`, `metrics.csv`, графики и отчёты.
   *Критерий: `metrics.json` содержит разделы и допущения, код возврата 0.*
5. **Сверить числа.** Сравните headline-показатели с `metrics.csv`.
   *Критерий: каждое число в тексте есть в `metrics.json`.*
6. **Написать выводы.** Используйте `templates/report.md.tmpl`.
   *Критерий: методология, допущения, интерпретация, риски, следующие шаги.*
7. **Отдать файлы.** Проверьте, что отчёт открывается и графики на месте.
   *Критерий: чек-лист из раздела «Проверка результата» пройден.*

## Входные данные

Клиентские таблицы: `clients`, `products`, `portfolio` (или `accounts`), `sales`
(или `applications`), `funnel_events`, `transactions`, `finance`.
Рыночные: `macro_deposits`, `macro_loans`, `macro_profit`, `macro_securities`,
`macro_survey`.

Полные схемы, типы и примеры — `references/data-dictionary.md`. Поддерживаются
CSV, XLS, XLSX. Широкие листы Excel разбираются адаптером `cbr_survey`: в режиме
`auto` он ищет книгу `stat_*.xlsx`, для другого имени нужен `--adapter cbr`.
Если таблицы нет, раздел пропускается с предупреждением, а не с нулём.

## Выходные артефакты

- `metrics.json` — разделы, допущения, предупреждения, контроль качества, headline
  (`value` — строка для отчёта, `raw` — то же число для XLSX и сверки).
- `metrics.csv` — плоский список чисел для сверки и трассировки.
- `charts/*.png` — графики, только если в данных есть что рисовать.
- `financial_analyst_report.{docx,pdf,xlsx,pptx,rtf}` — отчёт с таблицами и графиками.
- `report.html` — интерактивный дашборд (при рыночном ряде) или статический отчёт.

Интерпретацию и рекомендации скрипт не пишет: это делает агент по шаблону.

## Контроль качества

- `references/quality-gates.md` — проверки входа: ключи, связи, даты, валюты, дубли.
- `references/metric-contracts.md` — зерно, числитель, знаменатель, краевые случаи.
- `references/cohorts.md` — определение когорты и цензурирование.
- `scripts/finanalyst/reporting.py` (`lint_text`) — смешение алфавитов, двойные
  пробелы, латиница.

Жёсткие правила:

1. **Никаких чисел, которых нет в данных.** Запрещено подставлять «примерные»
   значения в таблицы и графики. Допущение — только отдельным блоком с пометкой.
2. **Никаких тихих NaN.** Если метрика не считается, это `null` и причина,
   а не ноль и не пустая ячейка.
3. **Одна метрика — одно определение.** Если определение меняется, меняется
   `metric-contracts.md`, а не отчёт.
4. **Строки `product_code = 'ALL'` не суммируются с детализацией.**
5. **Валюты не складываются без курса и даты курса.**

## Подводные камни

- **PDF без шрифта.** Helvetica не содержит кириллицы. Скрипт подставляет DejaVu;
  если шрифт не найден, он падает с понятной ошибкой, а не рисует квадраты.
- **Смешение периодов.** Месяц `2026-01` и квартал `1к02` — разные типы.
  Нормализуйте в `period_start` и сортируйте по дате, не по строке.
- **Воронка без `application_id`.** Считать можно только по клиенту, и это
  допущение, а не конверсия заявок. См. `references/cohorts.md`.
- **Немонотонная воронка.** Если клиент появляется на позднем этапе без ранних
  событий, конверсия «от лида» не имеет смысла. Проверяйте монотонность.
- **Пустой прогноз.** Если периодов меньше шести, прогноз не строится:
  лучше отсутствие графика, чем пустая картинка.
- **`finance` с `ALL`.** Итоговая строка вместе с детализацией удваивает выручку.

## Проверка результата

```bash
python scripts/analyze.py --data-dir assets/sample --out /tmp/fa --strict
python scripts/check_skill.py
```

Ожидается: код возврата 0, шесть файлов отчёта, `metrics.json` с разделами.
Дополнительно проверьте:

- PDF открывается и текст читается по-русски;
- XLSX: числа имеют числовой тип, а не текст;
- воронка монотонно убывает от лида к активации;
- PAR 30 ≥ PAR 60 ≥ PAR 90;
- в `metrics.json` нет `NaN`, только `null` с причиной.
