# Словарь входных данных

Имя файла = имя таблицы: `portfolio.csv`, `clients.xlsx` и т. д. Кодировка UTF-8,
разделитель определяется автоматически. Даты — ISO (`2024-01-31`) или Excel-date.

Общие правила:

- первая строка — заголовки, имена в нижнем регистре;
- суммы — числа, без пробелов и символов валюты внутри значения;
- пропуск — пустая ячейка, не `0` и не `н/д`;
- ключи (`client_id`, `product_code`) уникальны в своих справочниках;
- одна строка = одно наблюдение указанного зерна.

## 1. clients — клиенты

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| client_id | string | да | Уникальный идентификатор | C-12345 |
| segment | string | нет | Сегмент | массовый |
| region | string | нет | Регион | Москва |
| acquisition_channel | string | нет | Канал привлечения | приложение |
| registration_date | date | нет | Дата регистрации | 2024-01-15 |
| age | int | нет | Возраст | 34 |
| gender | string | нет | Пол | М |

## 2. products — справочник продуктов

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| product_code | string | да | Код продукта, уникальный | CC-01 |
| product_type | string | да | Тип продукта | кредитная_карта |
| product_name | string | нет | Название | Карта Базовая |
| interest_rate | decimal | нет | Ставка, % годовых | 24.0 |
| tariff | decimal | нет | Тариф за период, валюта | 1500 |
| cost_of_funds | decimal | нет | Стоимость фондирования, % годовых | 9.0 |
| reserve_rate | decimal | нет | Норматив резерва, % | 5.0 |

## 3. portfolio (или accounts) — счета и договоры

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| account_id | string | да | Уникальный идентификатор счёта | AC-99887 |
| client_id | string | да | Ссылка на clients | C-12345 |
| product_code | string | да | Ссылка на products | CC-01 |
| open_date | date | нет | Дата открытия | 2024-02-10 |
| close_date | date | нет | Дата закрытия | 2024-11-01 |
| limit_amount | decimal | нет | Лимит | 300000 |
| balance | decimal | да | Остаток или задолженность | 120000 |
| currency | string | нет | Валюта | RUB |
| status | string | нет | активен / закрыт / просрочен | активен |
| dpd | int | да | Дней просрочки | 35 |
| par_bucket | string | нет | current / 30+ / 60+ / 90+ | 30+ |

**Важно:** `par_bucket` — интервальный бакет (30+ означает 30–59 дней), а PAR
считается кумулятивно по `dpd`. Если бакеты и `dpd` расходятся, контроль качества
выдаст предупреждение, а расчёт пойдёт по `dpd`.

Несколько валют в одной таблице допустимы только для хранения. Для агрегатов
нужен пересчёт по курсу с датой; иначе суммы не сопоставимы.

## 4. sales (или applications) — заявки

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| application_id | string | да | Уникальный идентификатор заявки | APP-55432 |
| client_id | string | да | Ссылка на clients | C-12345 |
| product_code | string | да | Продукт | CC-01 |
| channel | string | нет | Канал продаж | колл-центр |
| manager_id | string | нет | Менеджер | M-77 |
| application_date | date | да | Дата заявки | 2024-02-05 |
| funnel_stage | string | да | Максимальный достигнутый этап | одобрение |
| stage_date | date | нет | Дата этого этапа | 2024-02-07 |
| result | string | нет | одобрено / отказано / отозвано | одобрено |
| amount | decimal | нет | Сумма сделки | 250000 |
| premium | decimal | нет | Страховая премия | 12000 |

**Важно:** одна строка = одна заявка с максимальным достигнутым этапом.
Этого достаточно для конверсии, но **недостаточно для TAT**: нужны события
по каждому этапу (таблица `funnel_events`).

## 5. funnel_events — события воронки

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| event_id | string | да | Уникальный идентификатор события | EV-11 |
| application_id | string | да | Ссылка на sales.application_id | APP-55432 |
| client_id | string | нет | Клиент | C-12345 |
| product_code | string | нет | Продукт | CC-01 |
| channel | string | нет | Канал | приложение |
| stage | string | да | Этап: лид…активация | заявка |
| event_date | date | да | Дата события | 2024-02-01 |
| campaign_id | string | нет | Кампания | CAMP-2024-02 |

**Зачем `application_id`:** без него нельзя восстановить прогрессию заявки.
При его отсутствии скилл считает этап максимальным достигнутым на клиента
и явно пишет это допущение в отчёт.

`stage` принимает только: `лид`, `обращение`, `заявка`, `одобрение`, `договор`,
`активация`. Неизвестная метка — ошибка данных, а не тихий `NaN`.

## 6. transactions — операции

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| txn_id | string | да | Уникальный идентификатор | TX-881 |
| account_id | string | да | Счёт | AC-99887 |
| txn_date | date | да | Дата | 2024-02-12 |
| txn_type | string | да | покупка / перевод / снятие / комиссия | покупка |
| amount | decimal | да | Сумма | 5400 |
| fee | decimal | нет | Комиссия банка | 54 |

`transactions` загружается, но в автоматический отчёт не попадает: операции нужны
для когортного анализа (`cohorts.md`), который выполняется отдельно.

## 7. finance — выручка и расходы

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| period | string | да | Период `YYYY-MM` | 2024-02 |
| product_code | string | да | Продукт или `ALL` | CC-01 |
| interest_income | decimal | нет | Процентный доход | 450000 |
| fee_income | decimal | нет | Комиссионный доход | 120000 |
| premium | decimal | нет | Страховые премии | 0 |
| funding_cost | decimal | нет | Стоимость фондирования | 180000 |
| reserve_expense | decimal | нет | Отчисления в резервы | 50000 |
| opex | decimal | нет | Операционные расходы | 200000 |
| marketing_cost | decimal | нет | Расходы на привлечение | 30000 |
| tax | decimal | нет | Ставка налога, доля 0…1 | 0.20 |

`tax` хранится справочно и в расчётах не участвует: отчёт показывает валовую и
contribution margin до налога.

**Правило `ALL`:** строка `product_code = 'ALL'` — итог. При суммировании
она исключается, иначе выручка удваивается. Контроль качества об этом предупреждает.

Если `marketing_cost` нет, CAC, LTV/CAC и окупаемость не считаются: в отчёте
будет `null` и причина, а не ноль.

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| period | string | да | `YYYY-MM` | 2026-01 |
| category | string | да | вклады_физлиц / депозиты_юрлиц | вклады_физлиц |
| currency | string | да | RUB / USD / EUR | RUB |

## 12. macro_survey — опросы предприятий

Длинная таблица, которую собирает адаптер `cbr_survey` из широких листов Excel.

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| period | string | да | `YYYY-MM` или `1к02` | 2026-01 |
| industry | string | да | Отрасль (имя листа) | Экономика всего |
| indicator | string | да | Показатель (заголовок колонки) | Индикатор бизнес-климата |
| value | decimal | да | Значение | 2.96 |
| unit | string | нет | Единица | баланс ответов, % |
| source_file | string | нет | Исходный файл | Stat_opros.xlsx |
| source_sheet | string | нет | Лист | Экономика всего |

Адаптер пропускает листы «Спецификации…» и «Участники опроса», находит строку
заголовков в первых семи строках и приводит месячные и квартальные периоды
к `period_start` + `period_type`. Смешивать типы в одном ряду нельзя: квартал
приводится к первому месяцу квартала и помечается `Q`.

В режиме `--adapter auto` адаптер ищет книгу с именем `stat_*.xlsx`; если файл
назван иначе, запустите с `--adapter cbr` — тогда проверяется любая книга
в каталоге. Готовую длинную таблицу можно подать и как обычный `macro_survey.csv`.

## Минимальный набор для запуска

- Портфель: `portfolio` + `products` (для типа продукта).
- Воронка: `funnel_events` или `sales`.
- Юнит-экономика: `finance` + `portfolio` (или `clients`).
- Макро: любая из `macro_*` или один xlsx-файл опросов.

Остальные таблицы опциональны: отсутствие раздела — предупреждение, а не ошибка.
