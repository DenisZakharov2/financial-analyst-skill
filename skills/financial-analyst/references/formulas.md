# Формулы

Все формулы приведены с обозначениями и единицами. Определения метрик, зерно
и краевые случаи — в `metric-contracts.md`. Если формула меняется, меняются оба файла.

**Соглашения**

- Денежные суммы — в валюте счёта; для агрегатов указывайте валюту явно.
- Ставки и конверсии — в процентах, в формулах умножаются на 100 в конце.
- Период — календарный месяц, если не указано иное.
- Знак: расходы положительные, выручка положительная, прибыль может быть отрицательной.

## 1. Юнит-экономика

### CAC — стоимость привлечения клиента

```
CAC = (маркетинг + выплаты каналам + ФОТ продаж + агентские) / новые клиенты
```

Единица: валюта на клиента. Скрипт берёт из выгрузки только `marketing_cost` и
делит на число клиентов с `registration_date` внутри периода. Если даты
регистрации нет, знаменателем становятся активные клиенты, и это явно
записывается в допущениях. Если расходов на привлечение нет, CAC = `null`,
а не 0: ноль меняет смысл LTV/CAC.

### ARPU — выручка на активного клиента в месяц

```
ARPU_мес = выручка_за_период / среднее_число_активных_клиентов / число_месяцев
```

Делить на число месяцев обязательно. Иначе LTV завышается во столько раз,
сколько периодов в выгрузке.

### LTV — пожизненная ценность

```
LTV_gross = ARPU_мес × маржинальность × срок_жизни_мес
LTV_net   = LTV_gross − CAC
```

`LTV/CAC` считается **по gross**: если вычесть CAC из LTV, отношение теряет смысл.

### LTV / CAC

```
LTV_CAC = LTV_gross / CAC        цель обычно ≥ 3
```

Если `< 1` — привлечение убыточно.

### Окупаемость CAC

```
Окупаемость_мес = CAC / (ARPU_мес × маржинальность)
```

Не `CAC / ARPU × маржа`: приоритет операций даёт другое число.

## 2. Рентабельность и маржа

```
Выручка        = процентный_доход + комиссионный_доход + страховые_премии
Прямые_расходы = стоимость_фондирования + отчисления_в_резервы
Валовая_маржа  = Выручка − Прямые_расходы
Маржинальность = Валовая_маржа / Выручка × 100
Contribution   = Валовая_маржа − операционные_расходы
```

`opex` в словаре включает обслуживание и привлечение; если нужно разделить,
заведите отдельные колонки, а не угадывайте состав.

```
NIM = (процентный_доход − процентные_расходы) / средние_работающие_активы × 100
ROA = чистая_прибыль / средние_активы × 100
ROE = чистая_прибыль / средний капитал × 100
```

`NIM` считается в годовых: поток за период делится на число месяцев выгрузки и
умножается на 12. Работающие активы приближены суммой остатков портфеля —
портфель в выгрузке является снимком на дату. `ROA` и `ROE` скрипт не считает.

### Страховая маржа

```
Loss ratio      = понесённые_убытки / заработанная_премия
Expense ratio   = (расходы на привлечение + администрирование) / заработанная_премия
Combined ratio  = Loss ratio + Expense ratio
Underwriting margin = 1 − Combined ratio
```

«Активы минус обязательства» — это капитал, а не страховая маржа.

## 3. Качество портфеля

```
PAR_N  = баланс_с_dpd_≥_N / общий_баланс_портфеля × 100
NPL    = баланс_с_dpd_≥_90 / общий_баланс × 100
Coverage = резервы / баланс_NPL × 100
```

PAR 30 ≥ PAR 60 ≥ PAR 90 по построению. Если это не так — ошибка в данных
или в разрезе. Бакеты `30+/60+/90+` в словаре заданы как **интервальные**;
для кумулятивных PAR используйте `dpd`, а не строку бакета.

## 4. Воронка

```
Дошедшие_i        = число заявок, у которых максимальный этап ≥ i
Конверсия_от_лида = Дошедшие_i / Дошедшие_1 × 100
Конверсия_этапа   = Дошедшие_i / Дошедшие_{i−1} × 100
```

Кумулятивный подсчёт гарантирует монотонность. Считать «уникальных клиентов
на этапе» нельзя: клиент может появиться на позднем этапе без ранних событий.

```
TAT_этапа = медиана(event_date_{i+1} − event_date_i)
```

TAT считается только если есть события по каждой заявке (несколько строк
на `application_id`). При одной строке на заявку TAT не рассчитывается.
Скрипт TAT не считает: формула нужна для ручного расчёта агентом.

## 5. Динамика и прогноз

```
Темп_роста = (Значение_t − Значение_{t−1}) / Значение_{t−1} × 100
CAGR       = (Значение_T / Значение_0)^(1/n) − 1
```

Линейный тренд:

```
y_t = a + b·t
```

Точность на бэктесте (последние k точек):

```
MAE  = mean(|факт − прогноз|)
RMSE = sqrt(mean((факт − прогноз)^2))
MAPE = mean(|факт − прогноз| / |факт|) × 100
```

MAPE не определён при `факт = 0`: используйте MAE/RMSE или исключайте нули.

Границы сценария:

```
пессимистичный = базовая_линия − band × MAE
оптимистичный  = базовая_линия + band × MAE
```

Это интервал ошибки модели, а не прогноз факторов. Для причинного прогноза
нужна регрессия с объясняющими переменными, которой в скилле нет.

## 6. Аномалии

```
Z = (x − среднее) / стандартное_отклонение          при n ≥ 50
Z_robust = 0.6745 × (x − медиана) / MAD             при n < 50
```

`MAD = median(|x − median(x)|)`. Порог `|Z| > 3`.

```
IQR = Q3 − Q1
верхняя граница = Q3 + 1.5 × IQR
нижняя граница  = Q1 − 1.5 × IQR
```

Z-score считать внутри однородной серии (одна категория, одна валюта, один
срок), а не по всей таблице: иначе сравниваются несопоставимые строки.

## 7. Макро-показатели

```
Доля_%        = значение_категории / сумма_по_разрезу × 100
Отклонение_%  = (факт − скользящее_среднее_n) / скользящее_среднее_n × 100
```

Индекс сезонности — к центрированной скользящей средней, а не к общему среднему:
при наличии тренда деление на общее среднее даёт смещение.

```
Корреляция_Пирсона  = cov(X, Y) / (σ_X × σ_Y)
Корреляция_Спирмена = корреляция рангов
p-value             = перестановочный тест, 2000 итераций
```

Корреляция не равна причинности. При множественных сравнениях указывайте,
сколько гипотез проверяли.

## 8. Единицы измерения

| Величина | Единица |
|---|---|
| Денежные суммы | валюта счёта (RUB, USD, EUR) |
| Ставки | % годовых |
| Конверсии, доли, PAR | % |
| Сроки | месяцы или дни, явно |
| Макро-суммы | млн руб. (рублёвый эквивалент) |
| Коэффициенты (LTV/CAC) | x |
