# Формулы

Все формулы приведены с обозначениями и единицами. Определения метрик, зерно и краевые случаи — в `metric-contracts.md`. Если формула меняется, меняются оба файла.

**Соглашения**

- Денежные суммы — в валюте счёта; для агрегатов указывайте валюту явно.
- Ставки и конверсии — в процентах, в формулах умножаются на 100 в конце.
- Период — календарный месяц, если не указано иное.
- Знак: расходы положительные, выручка положительная, прибыль может быть отрицательной.

## 1. Юнит-экономика

### CAC — стоимость привлечения клиента

```
CAC = marketing_cost / новые клиенты
```

Полная стоимость привлечения включает ещё выплаты каналам, ФОТ продаж и агентские. Скрипт этих колонок не видит и берёт только `marketing_cost`. Если даты регистрации нет, знаменателем становятся активные клиенты, и это явно записывается в допущениях. Если расходов на привлечение нет, CAC = `null`, а не 0: ноль меняет смысл LTV/CAC.

### ARPU — выручка на активного клиента в месяц

```
ARPU_мес = выручка_за_период / активные_клиенты_снимка / число_месяцев
```

Знаменатель — число уникальных `client_id` в снимке портфеля, а не среднее по периодам: отдельного ряда активных клиентов в выгрузке нет. Делить на число месяцев обязательно. Иначе LTV завышается во столько раз, сколько периодов в выгрузке.

### LTV — пожизненная ценность

```
маржа_доля   = Валовая_маржа / Выручка
LTV_gross    = ARPU_мес × маржа_доля × срок_жизни_мес
LTV_net      = LTV_gross - CAC
```

`Маржинальность` в разделе 2 — это уже проценты. В LTV и окупаемость подставляется доля, иначе LTV завышается в 100 раз. `LTV/CAC` считается **по gross**: если вычесть CAC из LTV, отношение теряет смысл.

### LTV / CAC

```
LTV_CAC = LTV_gross / CAC        цель обычно ≥ 3
```

Если `< 1` — привлечение убыточно.

### Окупаемость CAC

```
Окупаемость_мес = CAC / (ARPU_мес × маржа_доля)
```

Не `(CAC / ARPU_мес) × маржа_доля`: деление и умножение одного приоритета и считаются слева направо, скобки обязательны.

## 2. Рентабельность и маржа

```
Выручка         = процентный_доход + комиссионный_доход + страховые_премии
Прямые_расходы  = стоимость_фондирования + отчисления_в_резервы
Валовая_маржа   = Выручка - Прямые_расходы
Маржинальность = Валовая_маржа / Выручка × 100
Contribution    = Валовая_маржа - операционные_расходы
```

`opex` в словаре включает обслуживание и привлечение; если нужно разделить, заведите отдельные колонки, а не угадывайте состав.

```
NIM = (процентный_доход - процентные_расходы) / средние_работающие_активы × 100
ROA = чистая_прибыль / средние_активы × 100
ROE = чистая_прибыль / средний_капитал × 100
```

`NIM` считается в годовых: поток за период делится на число месяцев выгрузки и умножается на 12. Знаменатель — сумма остатков одного снимка портфеля, не среднее за период. Если у продукта указан тип, в знаменатель входят только кредитные типы (`кредит`, `кредитная_карта`, `overdraft` и соседние); вклады и страхование не входят. Тип не указан — строка остаётся в знаменателе. `ROA` и `ROE` скрипт не считает.

### Страховая маржа

```
Loss ratio     = понесённые_убытки / заработанная_премия
Expense ratio  = (расходы на привлечение + администрирование) / заработанная_премия
Combined ratio = Loss ratio + Expense ratio
Underwriting margin = 1 - Combined ratio
```

«Активы минус обязательства» — это капитал, а не страховая маржа.

## 3. Качество портфеля

```
PAR_N    = баланс_с_dpd_>=_N / общий_баланс_портфеля × 100
NPL      = баланс_с_dpd_>=_90 / общий_баланс × 100
Coverage = резервы / баланс_NPL × 100
```

PAR 30 ≥ PAR 60 ≥ PAR 90 по построению. Если это не так — ошибка в данных или в разрезе. Бакеты `30+/60+/90+` в словаре заданы как **интервальные**; для кумулятивных PAR используйте `dpd`, а не строку бакета.

## 4. Воронка и время прохождения (TAT)

```
Дошедшие_i       = число заявок, у которых максимальный этап ≥ i
Конверсия_от_лида = Дошедшие_i / Дошедшие_1 × 100
Конверсия_этапа  = Дошедшие_i / Дошедшие_{i-1} × 100
```

Кумулятивный подсчёт гарантирует монотонность. Считать «уникальных клиентов на этапе» нельзя: клиент может появиться на позднем этапе без ранних событий.

### Поэтапный TAT, SLA и зависший бэклог (`seasonality_tat.funnel_tat`)

```
TAT_{i -> i+1}     = event_date_{i+1} - event_date_i  (в сутках, при TAT ≥ 0)
TAT_p50            = median(TAT_{i -> i+1})
TAT_IQR            = Q3(TAT) - Q1(TAT)
SLA_compliance_%   = число_переходов_с_(TAT ≤ SLA_days) / общее_число_переходов × 100
Aging_days         = reference_date - last_event_date  (для незавершённых заявок)
```

Распределение времени обработки в финансах скошено вправо, поэтому основной центральной метрикой выступает медиана (`p50`) и квантили `p75 / p90 / p95`, а не среднее арифметическое. Незавершённые заявки (не дошедшие до финального этапа `активация` и не получившие статус `отказ` / `выдано`) выносятся в отдельную таблицу `aging_backlog`: смешивать их с завершёнными переходами нельзя из-за ошибки выжившего.

### Дискретная оценка удержания Каплана — Мейера по рангам воронки

```
hazard_i       = (Дошедшие_i - Дошедшие_{i+1}) / Дошедшие_i
KM_retention_i = prod_{k=1..i-1} (1 - hazard_k) × 100
```

`KM_retention` первого этапа равен 100 %: произведение по пустому набору предыдущих рисков. Это не оценка Каплана — Мейера по времени с цензурированием. Незавершённая заявка входит в «дошедшие» своим максимальным этапом и считается отвалом, а не цензурированным наблюдением. Зависший бэклог смотрите в `aging_backlog`.

## 5. Динамика, сезонность и каскадный прогноз

```
Темп_роста = (Значение_t - Значение_{t-1}) / Значение_{t-1} × 100
CAGR       = (Значение_T / Значение_0)^(1/n) - 1
```

Темп к предыдущему периоду: при нулевой базе значение — `null`, а не `∞`. YoY сравнивает период с тем же периодом год назад по календарю (на квартальном ряду это четыре строки, а не двенадцать). Он считается, только если медианный шаг ряда — месяц, квартал или полугодие; для дневного и недельного ряда колонка `yoy_pct` не строится.

### Декомпозиция сезонности (`seasonality_tat.seasonality_summary`)

Тренд $T_t$ оценивается центрированным скользящим средним с окном $P$ ($P = 12$ для месяцев, $P = 4$ для кварталов). Схема выбирается автоматически:
- **Мультипликативная** (если все $y_t > 0$):
```
S_raw(m) = median(y_t / T_t)  для месяца/квартала m = 1..P
S(m)     = S_raw(m) / mean(S_raw)
R_t      = y_t - T_t × S(m_t)
```
- **Аддитивная** (при наличии $y_t \le 0$, например для чистой прибыли или чистого притока):
```
S_raw(m) = median(y_t - T_t)  для месяца/квартала m = 1..P
S(m)     = S_raw(m) - mean(S_raw)
R_t      = y_t - T_t - S(m_t)
```

Сила сезонности $F_S$ и сила тренда $F_T$ (в диапазоне $[0; 1]$), в форме Хиндмана для аддитивного разложения:

```
F_S = max(0, 1 - Var(R_t) / Var(S_add_t + R_t))
F_T = max(0, 1 - Var(R_t) / Var(T_t + R_t))
```

В мультипликативной схеме в эту формулу подставляется аддитивный эквивалент сезонности $S^{add}_t = T_t \times (S(m_t) - 1)$, а не сам индекс $S \approx 1$: иначе в одной дисперсии смешиваются безразмерный индекс и остаток в деньгах. Индексы $S(m)$ считаются только по внутренней части центрированного среднего; края, где тренд достроен экстраполяцией, в медиану не входят.

Сезонные индексы рассчитываются только при длине ряда $N \ge 2P$ (минимум два полных цикла).

### Каскадный прогноз и метрики бэктеста (`forecast.forecast_advanced`)

> Модуль `forecast` входит в пакет с версии 2.1.0. Каскад выбирается флагом
> `--forecast-model`. Режим `legacy` по-прежнему считает линейный тренд
> (`metrics.forecast_trend`): границы сценариев там равны базовой линии
> ± `band` × MAE, без расширения по $\sqrt{h}$.

На скользящем бэктесте (последние $k$ точек, прогноз на 1 шаг) соревнуются три модели. Победитель — минимум MAE. RMSE, sMAPE и MASE считаются и пишутся в отчёт, но на выбор модели не влияют.
1. **Линейный тренд:** $y_t = a + b \cdot t$.
2. **Аддитивный Damped ETS** (Хольт — Уинтерс с затухающим трендом $\phi \in [0.80, 0.99]$). Сезонный член берётся по модулю длины сезона, поэтому формула верна и при $h > P$:
```
y_hat_{t+h|t} = L_t + (phi + phi^2 + ... + phi^h) × B_t + S_{t + ((h - 1) mod P)}
```
3. **ARX(1) с экзогенными драйверами.** В регрессию входит одновременный $X_t$, а не лаг. Прогноз на будущее возможен, только если задан `future_exog`; иначе модель — AR(1) с трендом:
```
y_t = w_0 + w_1 × t + rho × y_{t-1} + beta' × X_t + eps_t
```

Метрики точности на бэктесте:

```
MAE   = mean(|факт - прогноз|)
RMSE  = sqrt(mean((факт - прогноз)^2))
sMAPE = mean(2 × |факт - прогноз| / (|факт| + |прогноз|)) × 100
MASE  = MAE / mean(|y_t - y_{t-1}|)
MAPE  = mean(|факт - прогноз| / |факт|) × 100
```

`MAPE` не определён, если хотя бы один факт равен нулю: тогда `mape_pct = null`, а не среднее по ненулевым точкам. Точки, где и факт, и прогноз равны нулю, в sMAPE не входят; если таких валидных точек нет, `smape_pct = null`. Модель выбирается только по MAE. Знаменатель MASE — наивный прогноз случайного блуждания (лаг 1) на префиксе до первого фолда, а не сезонный $|y_t - y_{t-m}|$.

Границы сценария на горизонте $h = 1 \dots H$ расширяются пропорционально $\sqrt{h}$:

```
пессимистичный_h = базовая_линия_h - band × MAE × sqrt(h)
оптимистичный_h  = базовая_линия_h + band × MAE × sqrt(h)
```

## 6. Аномалии

```
Z = (x - среднее) / стандартное_отклонение         при n ≥ 50
Z_robust = 0.6745 × (x - медиана) / MAD             при n < 50
```

`MAD = median(|x - median(x)|)`. Порог `|Z| > 3`.

Если MAD = 0 (больше половины точек равны медиане), знаменатель вырожден: считается обычный Z по стандартному отклонению, а для константного ряда Z = 0. Так делает единственная реализация `metrics.robust_z`: ею пользуются и раздел аномалий в отчёте, и интерактивный дашборд, поэтому их числа совпадают.

```
IQR = Q3 - Q1
верхняя граница = Q3 + 1.5 × IQR
нижняя граница = Q1 - 1.5 × IQR
```

Z-score считать внутри однородной серии (одна категория, одна валюта, один срок), а не по всей таблице: иначе сравниваются несопоставимые строки.

## 7. Макро-показатели и лаговая причинность

```
Доля_%          = значение_категории / сумма_по_разрезу × 100
Отклонение_% = (факт - скользящее_среднее_n) / скользящее_среднее_n × 100
```

Индекс сезонности — к центрированной скользящей средней, а не к общему среднему: при наличии тренда деление на общее среднее даёт смещение.

```
Корреляция_Пирсона = cov(X, Y) / (σ_X × σ_Y)
Корреляция_Спирмена = корреляция рангов
p-value             = перестановочный тест, 2000 итераций
                      p = (k + 1) / (N + 1)  (поправка Фипсона — Смита)
```

### Лаговый F-тест Грейнджера с контролем FDR (`drivers.macro_lead_lag`)

На первых разностях $\Delta y_t = y_t - y_{t-1}$ сравниваются ограниченная модель (только собственные лаги $\Delta y_{t-1 \dots t-L}$) и полная модель (с добавлением лагов $\Delta x_{t-1 \dots t-L}$ при $L \le \lfloor T/5 \rfloor$):

```
F_stat = ((RSS_restricted - RSS_unrestricted) / L) / (RSS_unrestricted / (T_eff - 2L - 1))
p_search = min(1, p_min × число_проверенных_лагов)     (Бонферрони)
p_FDR(i) = min_{j >= i} (m × p_(j) / j)                (Бенджамини — Хохберг по парам)
```

$T_{eff} = T - L$ — длина регрессионной выборки, не длина исходного ряда. Знаменатель степеней свободы $T_{eff} - 2L - 1$ учитывает константу и $2L$ лагов. Лаг с минимальным p-value нельзя подставлять в FDR как есть: перебор лагов занижает p-value, поэтому перед поправкой по парам p-value домножается на число проверенных лагов.

## 8. Факторное разложение (PVM, сдвиг PAR и портфельный Bridge)

### PVM-декомпозиция выручки и выдач (`drivers.pvm_decomposition`)

Для двух периодов ($0$ и $1$) с объёмами $Q_{i}$, долями $s_i = Q_i / Q$, ставками $R_i = V_i / Q_i$ и средней базовой ставкой $\bar{R}_0 = V_0 / Q_0$:

```
Volume_Effect      = (Q_1 - Q_0) × s_{i,0} × R_avg_0
Mix_Effect         = Q_1 × (s_{i,1} - s_{i,0}) × (R_{i,0} - R_avg_0)
Rate_Effect        = Q_{i,0} × (R_{i,1} - R_{i,0})
Interaction_Effect = (V_{i,1} - V_{i,0}) - (Volume_Effect + Mix_Effect + Rate_Effect)
```

Сумма четырёх эффектов равна $\Delta V$ по построению: `Interaction` — это остаток $\Delta V$ минус три других эффекта, а не независимо оцененный четвёртый фактор. Ставка в `Rate_Effect` берётся на базовом объёме $Q_{i,0}$ (Ласпейрес). Для нового продукта ($Q_{i,0} = 0$) ставка базы подменяется ставкой цели, и цена нового продукта попадает в микс и остаток, а не в объём.

### Разложение сдвига просрочки PAR по Шепли (`drivers.par_shift_decomposition`)

Для весов продуктов в портфеле $w_{i,0}, w_{i,1}$ и ставок просрочки $r_{i,0}, r_{i,1}$ (в %):

```
Within_Risk_Effect_pp    = sum_i [ 0.5 × (w_{i,0} + w_{i,1}) × (r_{i,1} - r_{i,0}) ]
Structural_Mix_Effect_pp = sum_i [ 0.5 × (r_{i,0} + r_{i,1}) × (w_{i,1} - w_{i,0}) ]
Delta_PAR_pp             = Within_Risk_Effect_pp + Structural_Mix_Effect_pp
```

### Портфельный Bridge между двумя выгрузками (`comparison.portfolio_bridge`)

По ключу `client_id` изменение портфеля раскладывается на пять корзин: New, Churned, Expansion, Contraction и Flat. У Flat дельта равна нулю, поэтому сумма четырёх ненулевых корзин совпадает с суммой пяти. $\Delta B_{contraction}$ — отрицательное число, а не модуль сжатия. При $B_0 = 0$ темп роста и NRR равны `null`, а не нулю.

```
Delta_B = Delta_new + Delta_churned + Delta_expansion + Delta_contraction + Delta_flat
NRR_%   = sum_{retained} B_{i,1} / B_0 × 100
```

## 9. Оценка пилотов: A/B-тестирование и DiD (`experiments`)

### Проверка Sample Ratio Mismatch (SRM)

```
chi2_SRM = (N_c - E_c)^2 / E_c + (N_t - E_t)^2 / E_t
```

Если $p(\chi^2_1) < 0.001$, сплит трафика нарушен (`ab_srm_check = fail`).

### Снижение дисперсии CUPED и линеаризация ratio-метрик (Дельта-метод)

```
theta_CUPED = cov(Y, X_pre) / var(X_pre)
Y_cuped_i   = Y_i - theta_CUPED × (X_pre_i - mean(X_pre))
```

Для ratio-метрики $R = \sum \text{Num}_i / \sum \text{Den}_i$, агрегированной до уровня клиента $i$:

```
L_i = (Num_i - R_control × Den_i) / mean(Den_своей_группы)
MDE = (z_{1 - alpha/2} + z_{power}) × SE(diff)
```

Интервал разности долей — метод Ньюкомба (интервалы Уилсона по группам). p-value пропорций по-прежнему из объединённого z-теста. Решение `launch` / `stop_degradation` считает, что большее значение лучше, если не передан `higher_is_better=False` (флаг `--ab-lower-is-better`). U-тест Манна — Уитни считается по исходной метрике, даже когда среднее сдвинуто CUPED.

### Панельный метод разности разностей (Difference-in-Differences, DiD)

```
Y_{it} = b_0 + b_1 × Treat_i + b_2 × Post_t + ATT × (Treat_i × Post_t) + eps_{it}
```

Стандартные ошибки основной оценки — гетероскедастично-робастные ошибки Уайта (HC1). Они не кластеризованы по единице панели: на короткой панели p-value оптимистичен. Параллельность пре-трендов проверяется на периодах $t < t_0$ обычным (не HC1) t-тестом взаимодействия $\text{Treat}_i \times t$. Даты панели разбирает `core.parse_period`, поэтому принимаются и «2024-03», и «март 2024».

## 10. Сегментация клиентов (`segmentation.segment_clients`)

Квантильные ранги $R, F, M \in \{1, 2, 3\}$ комбинируются с флагом просрочки $\text{DPD} > 0$. Для кластеризации K-Means++ `log1p` применяется к остатку, давности и DPD. Число продуктов входит в шкалу как есть: у него нет длинного правого хвоста, и логарифм сжимал бы различия 1 и 2 продуктов. Дальше каждый признак делится на свой IQR:

```
x_scaled = (x_prepared - median(x_prepared)) / (Q3 - Q1)
Silhouette(i) = (b_i - a_i) / max(a_i, b_i)
```
