# Changelog

## 2.1.2 — 2026-11-14

Исправления по код-ревью (см. `CODE_REVIEW.md`): надёжность, дублирование и читаемость.

**Исправлено**

- `check_srm` возвращает явный `status` (`passed` / `failed` / `unavailable`); при недоступном scipy или вырожденных данных `p_value` и `chi2` — `null`, а решение A/B-теста принимается по `status`, а не по правдивости `srm_ok`.
- Контроль качества SRM в отчёте различает «пройден», «не проверен (причина)» и «нарушен» вместо единого сообщения о нарушении.
- Порог контрольной суммы ПДн считается через `math.ceil` вместо самодельного `int(-(-x // 1))`; выборка детектора ПДн для длинных колонок — детерминированный `sample(500, random_state=0)` вместо склейки head/tail, которая пропускала середину колонки.
- Пороги шага прогноза (дни → месяцы) вынесены в `_step_months_from_days` — единственный источник порогов вместо двух рассинхронизированных if/elif-цепочек.
- `seasonality_tat` больше не строит словарь продаж через `iterrows()` — переход на `itertuples()` ускоряет обработку больших выгрузок.
- `run()` в CLI разложен на стадии (`_Pipeline` + `_stage_*`) с общим хелпером `_safe_chart` для шести одинаковых try/except-блоков графиков; поведение не изменилось.
- `pyproject.toml`: зависимости переведены с жёстких `==` на диапазоны, верхняя граница Python `,<3.13` соответствует протестированной матрице; в dev-зависимости добавлен `pytest-cov`, убран дублирующий `pypdf`.
- CI: минимальные `permissions`, `concurrency` для отмены устаревших запусков и покрытие (`pytest --cov`).

## 2.1.1 — 2026-11-12

Исправления по ревью: формулы, которые расходились с кодом, и несколько тихих ошибок расчёта.

**Исправлено**

- `km_retention_pct` записывается до применения hazard текущего этапа: на первом этапе удержание 100 %, как в контракте, а не доля перешедших дальше.
- Возврат на более ранний этап воронки считается по времени события. Раньше журнал сортировался по рангу, и `backward_count` не мог стать ненулевым.
- Таблица TAT сортируется по рангу этапа, а не по алфавиту названия. В сводку попадает последний переход воронки, а не случайный.
- Сезонные индексы считаются только по внутренней части центрированного среднего, без линейно достроенных краёв.
- Тест Грейнджера больше не отдаёт в FDR голый минимум p-value по лагам: перед поправкой по парам p-value домножается на число проверенных лагов.
- Рекомендация A/B различает метрики «больше лучше» и «меньше лучше» (`--ab-lower-is-better`).
- Доверительный интервал разности долей — метод Ньюкомба с правильными плечами Уилсона и обрезкой до [-1, 1]. Раньше считался интервал Вальда; первая сборка Ньюкомба меняла плечи местами и выходила за 1.
- Линейный прогноз сортирует периоды через `parse_period`. Шаг горизонта берётся по разобранным датам: парсер `YYYY-MM` схлопывал дневной ряд в один месяц. MAPE при нулевом факте — `null`.
- sMAPE без валидных точек — `null`, а не 0.
- HMAC-токен — 16 hex-символов. `1` и `1.0` дают один токен. Без `FINANALYST_PII_KEY` отчёт говорит, что псевдонимы живут один запуск.
- Сообщение об отсутствии scipy больше не предлагает несуществующий extra `[analysis]`.
- DiD разбирает русские подписи периодов тем же `parse_period`. Если пре-тренды не на чем проверять, флаг не становится «пройдено».
- Окно ARPU/NIM — объединение календарных месяцев: год и месяцы этого года не складываются в 23.
- PVM и сдвиг PAR не суммируют строку `ALL` вместе с продуктами.
- Полугодие в каскадном прогнозе — шаг 6 месяцев, а не квартал. Сезонность ETS на бэктесте совпадает с финальной моделью.
- Bridge не выбрасывает отрицательные остатки. Нулевая база по-прежнему даёт `null`, а не 0 %.
- `stages_skipped` — число пропущенных этапов, а не разрыв рангов.
- Лаги Грейнджера сортируются по разобранной дате, не по строке периода.
- Пропуск в метрике A/B исключается, а не заменяется нулём. Интервал непрерывной метрики — t Уэлча, как и p-value.
- Детектор ПДн смотрит числовые колонки и ключи соединения, не принимает `product_name` за ФИО и не считает голое поле `name` персональным по одному названию.
- `маржа 2024` больше не разбирается как март. Понимаются `15.05.2024 13:45`, `1.5.2024`, `1 кв. 2024`, `2024.0`.
- Имя файла таблицы приводится к нижнему регистру (`Clients.csv`). Сезонность воронки берёт месяц через `period_ym`, а не срез первых семи символов.
- В дашборде `<` в JSON экранируется. В XLSX текст, начинающийся с `=+-@`, не становится формулой.

**Документация**

- Снято противоречие «модуль forecast есть / модуля forecast нет».
- `examples.md` больше не утверждает, что TAT, ETS, A/B и кластеризация не реализованы.
- LTV и отток когорты не смешивают долю и проценты.
- `tax` в словаре — сумма, как в примере, а не ставка 0,20.
- Режим ПДн по умолчанию описан как `strict`.
- В quickstart ожидаемый контроль качества совпадает с прогоном образца: 14 проверок, 0 fail, 1 warn.

## 2.1.0 — 2026-11-10

Перенос модулей `forecast`, `drivers`, `experiments`, `segmentation` из прототипов
в пакет `finanalyst` и подключение их к CLI. Реализованы этапы 2–3 дорожной
карты (`Improvement/improvement_plan.md`).

**Добавлено**

- `finanalyst/forecast.py`: каскад моделей прогноза — линейный тренд, Damped ETS
  (Хольт — Уинтерс с затухающим трендом), ARX с экзогенными драйверами. Модель
  выбирается на скользящем бэктесте по MAE; считаются RMSE, sMAPE и MASE
  (`MAPE` при нулевых фактах не определён и для выбора модели не используется).
  Интервал сценариев расширяется пропорционально `sqrt(h)`.
- `finanalyst/drivers.py`: PVM-декомпозиция (объём, продуктовый микс, ставка,
  взаимодействие) как тождество без остатка; разложение сдвига PAR по Шепли
  (риск внутри продуктов и сдвиг структуры); лаговый F-тест Грейнджера
  с поправкой Бенджамини — Хохберга (FDR) и ограничением лага `floor(T/5)`.
- `finanalyst/experiments.py`: A/B-тест с обязательной проверкой SRM, тестом
  Уэлча и Манна — Уитни, CUPED по доэкспериментальной ковариате, z-тестом
  пропорций и линеаризацией ratio-метрик (Дельта-метод) на уровне `client_id`;
  квази-эксперимент DiD с робастными ошибками HC1 и проверкой параллельности
  пре-трендов.
- `finanalyst/segmentation.py`: детерминированная матрица RFM + Risk
  (шесть бизнес-сегментов) и робастная кластеризация K-Means++ на `log1p`-
  признаках с масштабированием по IQR.
- Новые флаги CLI: `--forecast-model` (`legacy`/`auto`/`linear`/`ets`/`arx`),
  `--ab-test` с настройками (`--ab-metric`, `--ab-metric-type`, `--ab-denominator`,
  `--ab-pre-metric`, `--ab-group-col`), `--segment` и `--no-cluster`, `--drivers`
  и `--drivers-max-lag`.
- Новые проверки качества: `ab_srm_check` (fail) и `ab_assignment_overlap` (fail),
  `funnel_timestamps_monotonic` (warn), `min_series_length_for_seasonality` (warn).
- `scipy` в зависимостях (`requirements.txt`, `requirements.lock.txt`, `pyproject.toml`).
  Без scipy базовый расчёт работает как прежде, расширенные разделы сообщают,
  что модуль недоступен.

**Исправлено**

- A/B-тест: клиент, попавший в обе группы, больше не искажает результат —
  такие единицы исключаются, а результат помечается недействительным
  (`invalid_assignment_overlap`). Раньше разбиение по группам смешивало
  единицы рандомизации.
- A/B-тест считается до контроля качества: нарушение SRM останавливает строгий
  запуск с кодом 2, а не остаётся заметным только в отчёте.
- `core.STAGE_ORDER` перенесён в `core`: контроль качества и расчёт TAT
  используют один порядок этапов (циклического импорта не возникло).
- Разбор периодов в прогнозе идёт через `core.parse_period`, поэтому понимаются
  «2024-05», «1к24» и «январь 2024».

**Документация**

- Описание скилла в `SKILL.md` дополнено возможностями версии 2.1.0 и больше не
  обещает когортный анализ: модуля когорт в пакете нет, `references/cohorts.md` —
  это соглашения (определение когорты, окно, цензурирование), а не расчёт.
- `playbook.md`, `formulas.md`, `metric-contracts.md`, `data-dictionary.md` и
  `quality-gates.md` переведены из режима «дорожная карта» в режим «реализовано»
  с указанием флагов запуска.
- README: таблица возможностей, флаги расширенных расчётов и честный список
  ограничений (интервал ошибки вместо причинной модели, лаговая связь ≠
  причинность, недействительный результат при сломанной рандомизации).

**Тесты**

- `tests/test_advanced_modules.py`: 23 теста на контракты новых модулей —
  тождества разложений, блокирующие состояния пилота, детерминированность
  кластеризации, совместимость формата ответа прогноза.
- `tests/test_cli_extensions.py`: 8 тестов на новые флаги, включая остановку
  строгого запуска при нарушении SRM и неизменность отчёта без новых флагов.

## 2.0.1 — 2026-11-10

Исправления по итогам независимого аудита репозитория (замечания подтверждены
воспроизведением на текущем коде; неподтверждённые замечания не применялись).

**Исправлено**

- `client_csv.normalize()`: канонические таблицы (`portfolio`, `sales`,
  `funnel_events`) больше не вытесняются синонимами (`accounts`, `applications`,
  `funnel`). Раньше `accounts.csv` молча затирал `portfolio.csv` в каждом прогоне.
- `core.load_tables()`: чтение CSV с fallback на `cp1251` (выгрузка 1С/АБС больше
  не роняет прогон) и определение разделителя по заголовку — одноколоночные
  файлы читаются корректно, без порчи шапки (`value` → `alue`).
- Периоды: дневная детализация больше не считается дублями одного месяца
  (`finance_grain_unique` больше не даёт ложный `fail`); `parse_period` одинаково
  трактует «2024-05-01» и `Timestamp("2024-05-01")`; в `MONTHS_RU` добавлены
  сокращения месяцев (`янв`, `фев`, `сен` и др.); `period_labels()` использует
  аргумент `fmt`; `normalize_periods()` добавляет `period_ym` и `period_full`
  и сортирует по полной дате.
- `core.TOTAL_CODES`: итоговые строки распознаются и по `TOTAL`, `ИТОГО`, `ВСЕГО`,
  а не только по `ALL` — двойного счёта больше нет.
- `validate_inputs`: сравнение `dpd` и `par_bucket` нечувствительно к регистру,
  отрицательные `dpd` не попадают в `pd.cut`.
- `core.KNOWN_TABLES` дополнен именем `funnel` — таблица воронки больше не
  попадает в «нераспознанные».
- `comparison.compare_snapshots()`: при нулевой базе и ненулевом целевом значении
  `delta_pct` = `None` с пояснением, а не `0.0` — рост «с нуля» больше не читается
  как отсутствие динамики.
- `pii.py`: порог детекции ПДн по содержимому снижен с 30 % (50 % для ИНН) до 5 %
  для email и телефона — колонка с контактами у 10 % клиентов больше не проходит
  как безопасная. Для номеров карт и ИНН оставлен порог 25 %: контрольные разряды
  проходят около 10 % случайных чисел, и низкий порог приводил бы к удалению
  технических идентификаторов. `is_valid_snils()` отсекает номера с тремя
  одинаковыми цифрами подряд (правило СФР).
- `seasonality_tat.funnel_tat()`: TAT и SLA считаются только по смежным переходам
  между этапами; переходы с пропущенным этапом вынесены в отдельную таблицу
  `skipped_transitions` и больше не искажают норматив этапа. Возвраты на
  предыдущий этап в TAT не входят.
- `seasonality_tat._parse_dates_to_ns()`: векторный разбор дат вместо цикла на
  Python — заметно быстрее на больших воронках.
- `cbr_survey.py`: книга закрывается через контекстный менеджер и не парсится
  заново для каждого листа; дробные числа с запятой («1 234,56») больше не
  превращаются в `NaN` и не теряются; `_dedupe()` не создаёт коллизий заголовков.
- `visuals.py`: фигуры matplotlib закрываются в `finally` — при пакетной
  генерации графиков не остаётся утечек.
- `reporting.py`: текст в ячейках PDF переносится (`Paragraph`), ширины столбцов
  рассчитываются под полосу набора, кегль уменьшается для широких таблиц,
  изображения вставляются с сохранением пропорций.
- Тестовая фикстура `date_strings_daily` считает даты по календарю: числа 29–31
  больше не выпадали, из-за чего «соседние» даты отличались на 4 суток и
  искажались тесты TAT и дневных рядов.

**Документация**

- `description` в `SKILL.md` расширено со 60 до 300 символов и перечисляет
  ключевые сценарии: LLM-роутер теперь видит возможности скилла до активации.

  `segmentation` — они помечены как дорожная карта версии 2.1.0), уточнены

**Добавлено**

## 1.0.3 — 2026-11-05

Второй проход по ревью: метрики, которые считались на разных базах или
расходились между отчётом и дашбордом, плюс упаковка.

**Исправлено**

- `new_clients` считается только по клиентам со счётом в портфеле — той же базе,
  что и `active_clients`. Раньше знаменатель CAC брался из всего справочника
  клиентов (в примере 60 против 52 активных), и CAC делился на людей, которых
  нет в ARPU. Без портфеля остаётся документированный фолбэк на всех
  зарегистрированных; ноль новых клиентов больше не подменяется активными —
  CAC честно `null`.
- `accounts` в разрезе продуктов и в итогах — один счётчик (уникальные
  `account_id`): сумма по продуктам сходится с итогом даже при пустых ключах.
- Робастный Z реализован один раз (`metrics.robust_z`) и используется и в разделе
  аномалий, и в дашборде. Раньше на одном и том же ряду отчёт показывал аномалию,
  а дашборд — ноль.
- `metrics.csv` содержит ключевые показатели (`raw`, а не форматированную строку)
  и все числа юнит-экономики, поэтому шаг «сверьте headline с `metrics.csv`»
  выполним. У пустого прогона остаётся заголовок.

**Упаковка**

- `requirements.lock.txt` явно помечен как набор для Python 3.12: `pandas 3.1`
  и `numpy 2.5` не имеют сборок для 3.10/3.11, и `pip install -r` там падал.
  В `SKILL.md` то же самое сказано пользователю.
- CI на 3.12 ставит зависимости из lock-файла (а не из диапазонов), поэтому
  недоступный пин теперь падает в CI, а не у пользователя.
- Тесты упаковки: состав lock-файла совпадает с `requirements.txt`, версии
  попадают в его диапазоны, версия пакета одна в `pyproject.toml`, `SKILL.md`
  и `__init__.py`.

**Добавлено**

- Строка «Новые клиенты за период» в блоке юнит-экономики: видно базу CAC.

## 1.0.2 — 2026-11-05

Исправления после вычитки кода: случаи, когда валидные данные падали
с трейсбеком или давали завышенные числа.

**Исправлено**

- Невозможная дата (`2024-13`, `2024-02-30`, `0.2024`) больше не роняет разбор
  периода: значение становится `NaT`, срабатывает проверка `finance_periods_parsed`

- Пропуск в `dpd` больше не считается отрицательной просрочкой: это `warn`
  `portfolio_dpd_missing`, а не `fail` с текстом «OK», поэтому `--strict`
  не останавливает валидный портфель. Проверка `dpd`/`par_bucket` больше
  не сравнивает строки без `dpd`.
- Строки `product_code = 'ALL'` исключаются из сумм `finance` и `portfolio`,
  если в том же периоде есть детализация: раньше правило было только
  в документации, а выручка и баланс удваивались. Число исключённых строк
  пишется в `excluded_total_rows`, предупреждение — в отчёт.
- `change_pct` при нулевой базе даёт `null`, а не `inf`: в DOCX/PDF/PPTX
  больше не печатается «inf %», в XLSX значение не теряется.
- `yoy_pct` считается по календарю, а не сдвигом на 12 строк: на квартальном
  ряду он больше не показывает 1200 %. Для дневного и недельного ряда не строится.
- Готовая длинная таблица с текстовым `period_start` не падает с
  `AttributeError: .dt accessor`: подписи периодов и прогноз приводятся терпимо.

**Добавлено**

- Тесты на все перечисленные случаи: невозможные даты, пропуск `dpd`,
  `ALL`-строки, нулевая база темпа, квартальный и дневной YoY, текстовый
  `period_start`, провал контроля качества вместо трейсбека.
