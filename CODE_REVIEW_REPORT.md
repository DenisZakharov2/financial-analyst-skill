## Общая оценка

Репозиторий находится в очень хорошем состоянии. Это не типичный пет-проект, а аккуратно спроектированный инструмент с:

- чётким разделением ответственности (скрипт считает числа, агент пишет выводы);
- полной трассируемости всех чисел до `metrics.json`;
- сильной статистикой (SRM, CUPED, Delta-метод, Granger + FDR, Shapley для PAR, walk-forward бэктест);
- продуманной обработкой краевых случаев и ошибок;
- защитой от ПДн (HMAC-псевдонимизация, режимы strict/redact/off);
- качественной документацией (metric-contracts, formulas, data-dictionary, quality-gates, playbook);
- содержательными тестами (не только «запускается», но и контракты метрик + регрессии прошлых багов).

Предыдущие находки из `CODE_REVIEW.md` (монолитный `run()`, пины зависимостей, сэмплирование ПДн только head+tail, отсутствие `status` у SRM, CI и т.д.) **в основном закрыты** в 2.1.2. Текущий код можно считать production-ready для своего класса задач.

Ниже — оставшиеся мелкие проблемы и, главное, предложения по развитию, которые заметно повысят ценность скилла.

## Оставшиеся проблемы и дефекты

### 1. Устаревшие комментарии про segfault (низкий приоритет)

В нескольких файлах остались комментарии вида:

```python
# Avoid .map() which triggers segfault in pandas 2.2.3/numpy 2.1.3
```

Файлы: `pii.py`, `cli.py`, `reporting.py`, `core.py`, `metrics.py`, `visuals.py`.

**Проблема:** numpy 2.1.3 не совпадает с текущими диапазонами (`numpy>=1.26,<3`). Комментарии вводят в заблуждение и нарушают единообразие языка (остальной код и документация на русском).

**Как исправить:**
- Либо удалить комментарии, если проблема больше не воспроизводится на актуальных версиях.
- Либо актуализировать: указать точные версии, на которых воспроизводится, и добавить тест/workaround.
- Привести к единому стилю (русский или английский — лучше русский, как в `style-ru.md`).

### 2. Покрытие `cli.py` (~70 %) и `seasonality_tat.py` (~75 %)

Основная логика покрыта хорошо, но оркестратор и часть сложных путей (особенно комбинации флагов + ошибки) покрыты слабее.

**Рекомендация:** добавить интеграционные тесты на ключевые комбинации флагов (`--forecast-model auto`, `--ab-test`, `--segment`, `--drivers`, `--compare-dirs`) с проверкой структуры `metrics.json`.

### 3. Отсутствие статической типизации в CI

Код использует аннотации, но `mypy` (или `pyright`) не запускается.

**Рекомендация:** добавить `mypy` в CI с разумным уровнем строгости. Это дешево и снижает риск регрессий при рефакторинге.

### 4. Ограниченная масштабируемость на очень больших выгрузках

Чтение идёт целиком в память (`pd.read_csv` / `read_excel`). Для миллионов строк (типичный портфель банка) это может быть проблемой.

**Рекомендация (опционально):**
- добавить режим чанкового чтения для ключевых таблиц;
- или документировать ограничения по объёму (например, «рекомендуется < 500 тыс. строк на таблицу»).

### 5. Дублирование логики определения шага периода

Пороги дней для определения гранулярности (M/Q/Y) всё ещё частично дублируются между `metrics.py` и логикой периодов. Риск расхождения при изменении.

**Рекомендация:** вынести в одну функцию в `core.py` и использовать везде.

## Предложения по улучшению (повышение ценности)

Скилл уже закрывает сильный базовый контур (портфель + воронка + юнит-экономика + прогноз + A/B + сегментация + bridge). Чтобы сделать его заметно полезнее для банков и финтеха, стоит добавить следующее.

### Высокий приоритет (быстрая отдача)

1. **Когортный LTV и retention-кривые**
   Сейчас LTV считается с фиксированным `lifetime-months`.
   **Ценность:** реальные когорты (по месяцу первой сделки/активации) + кривые удержания + LTV по когортам.
   Это стандартный запрос от product/finance.

2. **Migration matrices и vintage analysis для портфеля**
   Матрицы перехода PAR-бакетов (current → 1–30 → 31–60 → 90+) и винтажный анализ.
   **Ценность:** классический инструмент риск-менеджмента и кредитного мониторинга.

3. **Сценарный анализ и sensitivity**
   Помимо forecast bands — возможность задавать сценарии (рост/падение ключевой ставки, изменение конверсии, отток).
   **Ценность:** ответы на вопросы «что будет, если…».

4. **Конфигурационный файл (YAML)**
   Вместо длинной строки флагов — `analysis.yaml` с параметрами (lifetime, horizon, thresholds, какие разделы считать).
   **Ценность:** удобнее для агента и для повторного использования.

5. **Автоматические structured insights**
   Скрипт может выдавать не только числа, но и структурированные наблюдения (например: «PAR30 вырос на X п.п., основной вклад — продукт Y, канал Z»). Агент потом формулирует текст.
   **Ценность:** снижает нагрузку на агента и повышает качество выводов.

### Средний приоритет

6. **Более сильный forecasting**
   - Поддержка `statsmodels` (SARIMAX, ETS с сезонной компонентой).
   - Hierarchical forecasting (по продуктам/регионам).
   - Калиброванные доверительные интервалы, а не только MAE-band.

7. **Кредитный риск (базовый)**
   - Расчёт PD/LGD/EAD на уровне портфеля или сегмента (если есть нужные поля).
   - Scorecard monitoring (PSI, KS, Gini) при наличии скоров.

8. **Улучшенный HTML-дашборд**
   - Фильтры (продукт, период, сегмент).
   - Drill-down.
   - Возможность экспорта отдельных графиков/таблиц.

9. **Адаптеры к внешним источникам**
   - Прямое чтение из PostgreSQL / ClickHouse.
   - Google Sheets / Excel Online.
   - Официальный API ЦБ (для макро).
   **Ценность:** меньше ручной выгрузки.

10. **Плагинная система метрик**
    Реестр метрик + возможность добавлять свои через простой контракт.
    Документация генерируется автоматически.

### Долгосрочно (высокая ценность, больше усилий)

11. **Streamlit / простой Web UI**
    Для пользователей, которые не хотят работать через CLI/агента.

12. **Шаблоны регуляторной отчётности**
    Готовые макеты под требования ЦБ (если это актуально для целевой аудитории).

13. **Интеграция с BI**
    Экспорт в форматы, удобные для Power BI / Tableau / Superset (или готовые дашборды).

14. **Memory-efficient режим**
    Чанковая обработка + агрегация на лету для очень больших портфелей.

15. **Property-based testing**
    `hypothesis` для проверки финансовых тождеств (суммы, PVM, bridge и т.д.).
